# Public context retrieval and review

CTX-001 first slice. Public retrieval is an optional owner-private aid to the seven-step discovery workflow. It does not establish customer evidence, permission for AI, or factual accuracy. Existing discovery links remain `link_not_read`; pasted/manual workspace documents are unchanged. New retrieved sources live separately and no provider adapter reads them in this slice. Parent CTX-001 remains partial until reviewed-source PDFs and source-fenced AI integration are delivered.

## Runtime and operator gate

Migration 19000 starts `firstten_private.public_context_policy.enabled=false`. A protected database operator must record a runtime-review SHA-256 and reference before enabling. The service role cannot change the policy. Root must verify the deployed function runs the reviewed Node HTTPS/DNS transport using a controlled public fixture, then narrowly enable it. Never auto-enable during deployment or reset a stop on later releases. Turn it off before changes to transport/runtime assumptions; the review hash is an operator evidence reference, not an automatically verified build attestation. No hosted or main-local policy activation is part of worker tests.

`probePublicContextCapabilities({data:{projectId}})` freshly verifies the bearer and active owner, then returns only Node version/major, transport contract `pinned-public-https-v1`, and synchronous DNS Resolver/HTTPS request/BlockList/isIP availability booleans. It makes no outbound request, imports no service client and changes no policy. This capability receipt does **not** verify deployed DNS, TLS, pinning or redirect behavior; a separate controlled network retrieval is required. The operator can bind reviewed source hashes plus the deployed capability and controlled-network receipts in `runtime_review_sha256`.

The implementation uses Node 22 `https.request`, a per-resolution cancellable DNS `Resolver`, and `net.BlockList`. It does not depend on a transitive HTTP client or DNS validation followed by an unrelated fetch. Explicit direct request options preserve Host/SNI, TLS certificate checks and pinned lookup, disable address-family fallback and pooling, and pass an empty proxy configuration. The socket must match the vetted address and be authorized before `req.end()` sends the request. No application cookie, authorization or referrer crosses the outbound boundary. Relevant primary APIs: [HTTPS](https://nodejs.org/docs/latest-v22.x/api/https.html), [DNS resolver](https://github.com/nodejs/node/blob/v22.23.1/doc/api/dns.md), [IP BlockList](https://nodejs.org/docs/latest-v22.x/api/net.html#class-netblocklist).

Only ASCII HTTPS URLs on443, without credentials/query/fragment/percent escapes, are supported initially. IP literals—including numeric/hex normalization—local/internal/reserved hostnames and ambiguous paths are rejected. A/AAAA answers are bounded and all must pass a conservative public-address policy. The selected address is pinned, never resolved again during connection. Reserved, private, loopback, link-local, multicast, mapped and transition addresses are denied. Conservative IPv6 exclusions may reject some legitimate sites; manual paste remains available. This is not a claim that every routable website is trustworthy.

At most two redirects are followed, on the original HTTPS origin only, with URL and DNS validation at every hop. Cross-host redirects, auth challenges, CAPTCHA, non200 responses and unsupported content fail closed. No scripts, images, stylesheets, frames or page links are fetched. HTTP URLs are not contacted to discover an HTTPS upgrade.

Limits:10-second whole retrieval,1.5-second cancellable DNS,3-second idle connection,16KiB headers,256KiB streamed site response. `Accept-Encoding: identity` is requested; compressed responses are rejected. UTF-8 decoding is strict and binary/control content is rejected. The parse5 parser is a pinned direct production dependency, not jsdom/browser execution. Static extraction omits head/scripts/style/template/noscript/frames/SVG and enforces bounded nodes/depth. The extracted text can still include navigation or hidden static content; it is not a verified rendered view. Overlarge text is rejected, never silently truncated. Plain text, Markdown and HTML are supported; PDF/images and other formats use manual text capture instead.

## GitHub

Only public `github.com/owner/repository` inputs are accepted. All API URLs are constructed on `api.github.com`; response download URLs are ignored and API redirects are rejected. Metadata must report `private=false`. The default branch is resolved once to a commit and tree. At most three explicit text files at the root or one directory level are selected, with README.md as default. Non-recursive trees must be complete and at most500 entries; only regular blob modes100644/100755 qualify. Symlinks, submodules, hidden files and dependency/build folders are excluded. Blobs are fetched by SHA, decoded as strict Base64, verified against their Git blob ID and bounded to64KiB before strict text/preview limits. Whole file text must fit the 24 KiB preview cap; larger files fail with `SOURCE_TOO_LARGE` before blob download rather than being truncated or marked read. A large README can be replaced by an explicitly selected smaller permitted file, or a reviewed excerpt pasted into manual context. Requests are sequential, at most ten API GETs and the same10-second total deadline. No clone/archive/recursive crawl, credentials, dependency installation or repository execution occurs.

GitHub's contents API can return symlink targets as files, so mode checks use the [Trees API](https://docs.github.com/en/rest/git/trees). [Blob API](https://docs.github.com/en/rest/git/blobs) responses provide Base64 data. Public unauthenticated access has a [60-request/hour originating-IP limit](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api); a shared classroom deployment may exhaust it quickly.403/429 retains manual paste and never triggers a credential request or automatic retry.

Repository metadata is an unverified author claim retrieved at a time, not a commit-versioned customer observation. File provenance records the immutable commit/path/blob IDs and SHA-256 of literal decoded text. The separate preview hash binds the exact text shown for review. Website content hashes bind raw fetched bytes; preview hashes bind extracted static text. Neither hash establishes truth or legal permission.

## Data and permission contract

All four new relations are in `firstten_private`, RLS enabled with no raw browser/service grants:

- `public_context_policy`: protected operator stop/runtime evidence.
- `public_context_operations`: owner/project, stable intent hash, kind, attempt nonce, lease/state/times and safe failure enum; no prompts, response bodies, raw network errors or credentials.
- `public_context_previews`: bounded successful source DTOs with server-created IDs/retrieval/expiry timestamps.
- `reviewed_public_sources`: immutable selected excerpt/label/hash/review time and a mutable active/withdrawn revision. AI/sharing are fixed `unknown`; no grant API exists here.

The user explicitly confirms permission to retrieve/store a private preview. Every server function freshly verifies the bearer using `getUser`. Retrieval additionally confirms the current active owner before importing service access. The service-only begin RPC takes a global policy lock, weak auth-owner deletion lock, project lock, then operation lock. It authorizes one30-second lease with a random nonce and counts starts conservatively:3/minute and20/rolling24hours per user,1 active/user across projects and10 active globally. Failed/expired work still consumes start allowance. Replayed intents never authorize another outbound request. Lost begin acknowledgments never dispatch. An expired nonce cannot complete after a replacement lease. Service completion rechecks policy, locks the auth owner KEY SHARE, project and operation, verifies current ownership/archive/lease/nonce and atomically saves all bounded source records. A source bundle is not partially presented as successful.

Preview text is at most24KiB per source, without complete HTML, cookies or raw network failures. Recent unreviewed previews are owner-readable for15minutes. **Expiry restricts access; physical deletion/purge is not implemented or promised.** PRV-002 owns retention. Secret-pattern scans are supplemental and cannot prove absence of sensitive information; users must not enter credentials, access tokens or sensitive participant data.

Review requires an exact substring of that unexpired preview, expected preview hash, a label and explicit owner-reported storage permission. The server stamps review time. Excerpts are at most6,000 Unicode characters/24KiB; altered text cannot masquerade as a retrieved excerpt. One immutable selection exists per preview. Repeated identical review is idempotent; another selection needs a new retrieval/version. At most20 reviewed versions are retained per idea, including withdrawn history. Capacity returns an explicit message rather than discarding old versions.

Withdrawal is owner-only CAS, including archived owner recovery, and advances a safe integer revision. The final safe revision is reserved for withdrawal, avoiding an unrevocable active source. Current list/withdrawal DTOs hide withdrawn text, label, URL and hashes. Retained history is not deleted. Owner read/export recovery is allowed on archived projects; new retrieval/completion/review remains blocked. No teacher, student, collaborator or platform-admin marker grants access. Auth-owner locks are KEY SHARE rather than an exclusive user lock to remain compatible with legacy project/child FK insertion patterns.

## API and DTO handoff

`src/lib/context.functions.ts` exports:

- `retrievePublicContext({data:{projectId,operationId,kind,url,paths,previewPermission:true}})` → `{ok:true}` or bounded failure. No source text is supplied by its browser request.
- `loadPublicContext({data:{projectId}})` → `{ok:true,previews,reviewed}` or bounded failure. Type `PublicContextList` is runtime validated.
- `reviewPublicContext({data:{projectId,previewId,expectedHash,label,excerpt,storagePermission:true}})` → authoritative reviewed-source DTO.
- `probePublicContextCapabilities({data:{projectId}})` → owner-only synchronous runtime capability receipt; no network verification or privileged toggle.
- `withdrawPublicContext({data:{projectId,sourceId,expectedRevision}})` → redacted withdrawn-source DTO.

Unreviewed preview fields: `id,projectId,operationId,previewPermission:true,kind,retrievedAt,expiresAt,source`. SQL derives the project and permission attestation; the runtime schema validates the entire projection.

Active `ReviewedPublicSource` fields: `id,previewId,projectId,reviewedAt,revision,status,label,excerpt,excerptHash,storagePermission,aiPermission,sharingPermission,source`. Metadata `source` contains `url,title,format,contentHash,previewHash,bytes,commitSha,path,blobSha`; it excludes full preview text. Withdrawn rows expose only IDs/review time/revision/status. Future owner PDFs must fetch current owner-authorized rows, filter/redact withdrawn content, and preserve public-author-claim/unknown permission labels. Exports must not silently omit a failed data acquisition.

The separate `RemoteContextPanel` keeps drafts independent of the manual discovery document, keys UI state by verified owner/project, ignores late responses after scope changes, protects local review drafts during refresh, and requires explicit read/storage confirmations. Rendering uses escaped text only. No retrieved URL is relabeled as read in the legacy document, no arbitrary HTML is rendered and no OpenRouter/provider request is introduced.
