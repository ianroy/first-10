# Account-free manual Marketing Lab

This is the remaining manual Next 50 channel/content/outreach slice of CLS-008. It has genuine guest principal/team ownership. It does not create an `auth.users` row or account project, change the seven-step Discovery contract, enable AI, contact anyone, collect analytics or grant teachers access to these plans. Reviewed teacher handoff for this plan kind remains separate work.

The desktop workspace follows five steps:

1. Think first: record observations, reachable people, a useful action and own channel ideas before preserving the original thinking. Refine the beachhead, situation, value proposition, assumptions and source notes separately.
2. Map channels: physical/digital places, observed fit, permission/access state, rules and where they were checked, time estimate, uncertainty/response bias; choose a primary channel and alternative with a reason.
3. Make content: a truthful hook, support, message or demo script, builder disclosure, one action, destination and useful product action; reported review and self/peer walkthrough. Separate respectful outreach drafts include permission/interview/product-test/follow-up purpose and manually reported response status. The app never sends them.
4. Plan the test: fixed $0 cash budget, available time, existing resources, limits/fallback, falsifiable hypothesis, primary metric, unknown-or-zero baseline/target, measurement plan, repeat/revise/stop criteria, dates, bounded actions and completion definitions. Statuses are student reports, not independent completion evidence. Prerequisites are prose in this guest subset, not an enforced dependency graph.
5. Review learning: manual measurement with a channel and optional matching content, metric, cohort, inclusive time window, unit, unknown-or-zero count, source, record date and limitations; select measurements for a repeat/revise/stop reflection. No conversion rate is inferred. The owner Marketing Lab's attribution tags and derived compatible-cohort rates are not implemented here.

## Authority and storage

`firstten_private.guest_marketing_plans` and `guest_marketing_operations` have RLS enabled and no anonymous, authenticated or service-role raw table grants. Only fixed public list/load/save functions are callable by the server's service role. Server functions use the existing same-origin POST, bounded-body, HttpOnly cookie and session-bound CSRF transport. Caller-controlled user/project/class/team IDs cannot authorize work.

Each RPC takes the existing class lock, resolves the current guest session, locks the team/principal scope and resolves it again. Reads recheck expiry before return. Saves recheck after the document/receipt write; crossing the deadline raises inside the caught subtransaction, rolling back the whole write. Five-second lock timeouts and the shared 120/minute guest-operation limiter apply.

Audience is immutable. Principal-private work can be read/edited only by its principal. Team-shared business text can be read/edited by current and future authorized team members; its author remains fixed. Team creation requires a separate audience confirmation and starts from a blank local document, never an automatic copy of private work. There is no raw-interview/source-record import surface or teacher query. People must not paste private participant notes or personal contact details into team business text. The shared audience itself cannot be withdrawn per author in this slice; teachers can close/revoke guest access through the existing controls. This limitation is disclosed rather than represented as a consent or deletion feature.

There are at most 3 private plans per principal and 5 shared plans per team, with 2,000 successful save receipts per principal. Reads and exact retries remain possible at capacity. No separate publication grant or AI/sharing permission is created, so there is no permission withdrawal endpoint to block at capacity. Existing seven-step/snapshot withdrawals are unaffected. Class/session expiry, revocation, recovery and rotation preserve the existing guest lifecycle. Access expiry is not verified data deletion, and previously downloaded PDFs cannot be recalled.

Closed documents have no account references or AI-origin fields, are at most 262,144 bytes, and have bounded collections/text. The same Zod-derived field shape is pinned in SQL, with semantic reference/uniqueness/date checks in both tiers. SQL normalizes text and enforces immutable preserved initial thinking. The server returns only validated response DTOs, with `aiEnabled: false`.

## Save and recovery semantics

Each save captures a stable plan ID, mutation ID, normalized sent document, audience and expected revision. Hashes bind all of those inputs. Exact retry returns the original acknowledged revision and current authorized record separately; it never writes the old content again. Reusing the ID for a changed request is denied. A stale teammate's revision conflicts. Class locking serializes creation/cap checks, saves and authority changes.

The browser retains local edits during requests and conflicts. An unconfirmed save retains its exact sent request for deliberate retry, even if the learner edits further. A replay indicating a newer remote revision does not replace the local draft. Opening another plan or creating a blank scope asks before discarding dirty/unconfirmed work. The parent receives an aggregate dirty signal, and the Router/before-unload guard covers navigation. Class/team/principal/CSRF key changes remount the editor and ignore stale responses. Unsaved work remains in memory only; there is no promise of offline persistence or recovery after closing the browser.

## PDF coverage and integration handoff

`guestMarketingActivities` emits individually selectable thinking, audience/value proposition, each channel, each content/demo, each outreach draft, test plan, each action, each measurement, and reflection. Every record is exported without truncation; `boundedOffers` splits oversized sections into named parts. The common picker supports selected portfolios up to 50 activities; a larger plan can be exported in multiple reviewed selections. Unsaved work, fictional fixtures, manual statuses, unknown counts and source/audience limits remain labeled. Private plans permit only owner scope; shared plans permit owner/team scope. Teacher export is denied for this kind.

Before both PDF generation and delivery, the guest export callback bootstraps the current cookie session, checks exact class/team/principal/CSRF and deadline, then reloads the exact saved plan revision/document if one exists. Local draft/scope changes invalidate review. No account source is fetched, no provider runs and nothing is submitted by download.

Root integration must mount `GuestMarketingWorkspace({ view, csrf, onDirtyChange })` within the guest room, combine its dirty flag with the seven-step studio flag, register `guestMarketingActivities` and its real mount in common export coverage, and regenerate official Supabase types after approved migration integration. Root owns those shared files and deployment. Broader guest activity parity, optional account transfer and teacher/team bundles remain unfinished.
