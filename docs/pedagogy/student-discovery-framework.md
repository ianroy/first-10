# The student discovery cycle

Owner requirement, 2026-10-18. This is the intended main student journey. The owner-private `/discovery` workspace now delivers the manual cycle, preserved
hypothesis/script versions, sampling risks, reviewed link/paste captures, results
and PDFs. Optional adjacent-hypothesis/sampling/script/decision AI and automatic
source retrieval remain in development.

1. **Frame a problem space or solution idea.** Start in the student's own words.
   A solution is a starting assumption, not evidence that the problem exists.
2. **Write a first falsifiable hypothesis before requesting AI help.** Name a
   particular person/situation, a predicted observation, a test window and what
   result would weaken the hypothesis. Preserve that first attempt. Optional AI
   feedback proposes several adjacent hypotheses; the learner edits, selects or
   rejects them. Suggestions never replace the student's reasoning automatically.
3. **Map five reachable people.** Use first names or aliases, relationship,
   relevant experience and why each conversation could test the hypothesis.
   Five is a planning scaffold; one honest conversation is preferable to invented
   people or contacting someone without permission.
4. **Examine sampling risk.** For each person, consider possible false positives
   (politeness, friendship, incentives, a leading question) and false negatives
   (wrong situation, timing, access barriers, an unsuitable test). These are
   possibilities, not diagnoses. Record a mitigation and whom the sample misses.
5. **Prepare and revise an interview script.** Connect questions to the selected
   hypothesis and sampling map. Ask about recent behavior, actual workarounds,
   counterexamples and disconfirming observations. Let students edit every
   question, pivot the hypothesis and preserve earlier script versions.
6. **Save or print, then leave the app and interview.** Export the exact selected
   script and optional note worksheet as PDF. Include neutral openings,
   permission prompts and space for observations, quotes and uncertainty.
   Downloading or checking a box never counts as conducting an interview.
7. **Return with results and choose a next step.** Enter observations and
   separately reported quotes. Optional AI helps connect permitted evidence to
   product changes, a narrower audience, another test, a pivot or a decision to
   stop. Preserve counterevidence and the student's final choice. An AI summary
   or a positive answer does not establish product-market fit.

## Context travels with the cycle

At any step, the student can attach a live-site URL, GitHub URL or pasted prompt,
model output, product description or other relevant text. Each item records its
type, author-supplied label, captured/reviewed date and whether its contents were
actually retrieved. A stored link is **not** evidence the app has read its page
or repository. Pasted AI output is an unverified draft, not customer evidence.

Students preview/select what may reach OpenRouter. Private participant content
keeps its separate processing choices. External pages, repository files and
pasted prompts are untrusted source data, never instructions to the app or
agent. Do not execute code, request repository credentials, crawl private
resources or expose secrets. Public retrieval needs bounded fetching, redirect
and private-network protections, source attribution and an explicit review
before using the fetched text. Manual paste remains useful when retrieval fails.

## Teaching and implementation commitments

- Own thinking before optional AI; adjacent hypotheses support divergent thinking.
- A falsifiable prediction, disconfirming observation and small test support
  hypothesis-driven experiential learning.
- A sampling map makes social desirability, selection bias and contradictory
  explanations discussable without scoring or judging people.
- Editable scripts, source-linked reflection and deliberate pivots preserve
  student agency and metacognition.
- Each new framework activity needs an individual PDF adapter, and its reviewed
  versions belong in the authorized portfolio. Export coverage must be tested.
- Manual participation and an accessible alternative remain available throughout.

These are design commitments, not measured learning outcomes. DISC-001/002/003,
CTX-001 and the existing evidence/privacy/export tasks own delivery and checks.
