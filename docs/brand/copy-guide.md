# First Ten product voice

Use a calm field notebook voice: clear next actions, visible uncertainty, respect for the person and their time. The desktop workspace uses persistent navigation, a named project context and readable cards so a workshop audience can follow the reasoning.

- Say what was recorded: completed conversations, manually reported outreach status, saved learning records. Counts are scaffolds and do not establish demand.
- Keep AI output labeled as an editable draft. A proposed experiment has no result until the owner records one.
- Preserve disagreement. A useful decision may be to stop, narrow the audience or retain a choice with a stated reason.
- Explain empty states with a next action that matches the actual stage. A Stage 2 project with no outreach contacts is empty, not locked.
- Show errors and a recovery action. Do not call a write saved before it succeeds. Account creation never grants admin access.
- Name inputs and controls explicitly for keyboard and assistive technology. Do not use placeholders as their only label.
- Mark the fictional presenter workspace on every shell page. Its people, conversations and proposed test are teaching examples, not research or adoption.

The public example needs no login. Personal work uses Supabase Auth; sign-in supports email/password, an explicitly configured demo username and email links. A new account starts with a private project. Separate projects, teacher class spaces and collaboration require their own implementation and permission gates.

Desktop navigation leads to the learning ladder, people, interview, learnings, outreach, account tools and teaching resources. Trusted presenter admin navigation is a convenience; the server independently verifies authorization on every aggregate request.
