# Privacy choices and external processing

PRV-001 · 2026-10-18 · implementation contract for migration `20261018011000`

First Ten now records separate owner-reported choices for keeping notes, external AI processing and reviewed sharing. These records document what the signed-in owner reports; they do not independently verify participant consent, a legal basis, institutional approval or FERPA compliance. See the [FERPA-first direction](privacy/ferpa-first-product-direction.md) and [access contract](architecture/access-contract.md) for the broader classroom boundaries. Guest class spaces and institution agreements remain separate work.

## Choice record and authority

Each private choice belongs to an owned project and one exact typed target: that project, a contact, an interview or a learning record. A target in another idea is rejected even when the same person owns both ideas. Unrelated users, teachers, project members and platform admins gain no authority to read or set these private choices. The server verifies the current user; database RPCs derive the actor from `auth.uid()` and recheck target ownership. There is no client actor/role field or service-role bypass.

The three independent states are `unknown`, `granted`, `declined` and `withdrawn`, under policy version 1. Saving one purpose never grants another. Absence of a row means all purposes are unknown, revision zero and no recorded report time. **Existing and fictional presenter records are not backfilled as granted.** A save records server time and a revision; stale saves must reload. The final JavaScript-safe revision is reserved for removing all grants, so exhaustion cannot trap an active purpose.

`reported_at` is when the owner saved the report, not when a participant supposedly gave permission. The note-taking checkbox is an owner attestation. Interview wrap-up saves its reported note choice and the separately selected AI/sharing choices in the same database transaction as the notes. The initial AI and sharing states are unknown. Capture failures roll back the interview, report and contact update together. A retry identifier returns the original acknowledgement rather than creating another interview or reapplying old choices.

The authenticated Interview page offers project and record privacy controls, saved-state timestamps, a manual question-writing path and an explicit learning-invalidation explanation. No external AI call is needed to set choices or complete an interview manually.

## Provider-request boundary

All AI continues through `generateAI`. The existing fresh-user provenance check runs, then `get_ai_processing_context` supplies an owner-authorized permission snapshot immediately before the provider request. A missing/declined/withdrawn project AI choice stops every ordinary AI kind. Missing record choices exclude that record; a query failure or malformed response fails closed, with no raw-table fallback. Questions use project details only. Other kinds use only their allowed record projections. Omission counts warn the model not to treat the remaining material as complete evidence.

The app server sends allowed text to OpenRouter and its routed model provider. This task does not verify provider retention settings, data residency, account eligibility, institutional contracts or a lawful basis for student data. General routing/privacy hardening remains AI-004/005/007 and institutional review remains FERPA-002. The separate fixed fictional practice route is not permission to process private student material.

The existing context builder still slices serialized segments and the existing gateway applies its request-size ceiling. Whole-source selection and stable production source references remain AI-007; this task must not be represented as that complete contract. The evaluation loader rejects oversized/truncated evidence instead of counting it as a valid evaluated case.

## Withdrawal and derived text

Withdrawal affects future permission snapshots. It does not erase saved private notes, cancel a request already transmitted, recall provider copies, remove a prior generated draft, retract an already viewed submission or delete a downloaded PDF. A request whose snapshot completed just before withdrawal can already be in flight; no recall guarantee is made.

Without trusted source lineage, the app conservatively withholds accepted learnings whenever any completed interview or contact is currently ineligible. A withdrawal/decline, or loss of an earlier grant, also invalidates all existing learnings in that project, records a content-free history event and resets their AI state to unknown. Ordinary regrant cannot clear that invalidation marker. Restoring the original source choice does not silently restore summary permission. Owners can keep working manually; source-linked review/redaction requires AI-007 before those invalidated summaries can be reused by AI.

These choices currently attach to **mutable records, not exact content versions**. Editing a previously approved record does not automatically prove renewed participant authorization or invalidate every downstream draft. The system cannot recognize deliberately copied text, a newly created manual summary containing an old quote, or content pasted into another project description. Existing-learnings invalidation and current-source eligibility checks reduce automatic reuse; they are not semantic tracking of every copy. Versioned authorized-source lineage, content-revision checks and reviewed redaction remain outstanding. Do not claim the choice record proves an unchanged artifact or complete withdrawal propagation.

## Sharing, export and retention limits

A sharing choice is a prerequisite report, not an access-control grant. It does not publish a snapshot, create class membership or give instructors raw interview access. Future sharing/submission/export services must independently enforce the intended audience, selected content, current grants and withdrawal. Current owner access to private work is preserved even when processing is declined. Activity PDF/export scope and reviewed team portfolios belong to EXP-001/002/003; this task does not implement them or remote recall of exported copies.

Choice history is append-only and intentionally contains no copied notes, prompts or generated bodies. UUIDs and linked metadata may still be personal/education-record data; they are not claimed anonymous. Parent-project deletion cascades current choice rows; private history and retry metadata are retained by this migration. No account deletion, retention schedule, provider deletion or operator purge is implemented here. PRV-002 must define institution-appropriate retention and a narrowly authorized, audited purge procedure, including the controlled exception needed for append-only metadata. Do not disable history protections as an ad hoc cleanup.

## Verification boundary

The PRV suite checks owner/project separation, unknown historical states, independent purposes, source filtering, denied teacher/admin access, withdrawal-driven learning invalidation, blocked regrant, safe-integer revocation and exactly-once capture acknowledgement. It injects a mid-transaction consent-write error to prove no interview or acknowledgement survives that failure. Provider tests assert permission failures never call the gateway or fall back to raw child tables. UI tests cover separate controls, explicit save/reload, visible manual paths and permission gating.

Actual hosted migration, deployment and signed-in browser verification are coordinator release steps. No paid AI call or institutional compliance determination is part of these software checks.
