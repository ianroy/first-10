## Schema, billing and privacy eligibility

Structured-output support belongs to the endpoint. Retain `response_format.type=json_schema`, `strict:true`, `require_parameters:true` and independent application/grounding validation. OpenRouter cautions that strict enforcement varies by provider. The schema includes the `{draft,grounding}` wrapper; valid JSON alone cannot establish source accuracy or sound pedagogy. No response-healing plugin or hidden repair request is approved. [Structured outputs](https://openrouter.ai/docs/guides/features/structured-outputs).

Reasoning is billable output. OpenRouter says it counts within `max_tokens` **on most providers**, not all; suppressing returned reasoning is not a billing cap. Google's current thinking guide describes the 2.5 thinking budget as soft and dynamically chosen when omitted; it can be disabled with the upstream budget setting. The current gateway does not send an explicit reasoning setting. Do not repeat the older plan's assumption that this route necessarily defaults to disabled thinking. Require endpoint-specific evidence that the exact OpenRouter request bounds **total** charged reasoning plus visible output at 2,500. Gemini 3 thinking levels are not precise token budgets. Without that evidence, keep the route unavailable. [OpenRouter reasoning](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens), [Google thinking controls](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/thinking).

`max_price` is a unit-price filter in USD per million tokens, not a per-request dollar limit. Keep prompt/completion ceilings and the atomic reservation together. Public prices and a successful schema declaration cannot rule out separate charges. Approve text-only requests with no tools, search, media, plugins or explicit caching; review implicit/cache billing, fees and response usage before claiming the all-in bound. [OpenRouter price filtering](https://openrouter.ai/docs/guides/routing/provider-selection#max-price).

Privacy has several independent layers:

- OpenRouter says prompt/response storage is opt-in through private input/output logging or product-improvement use; request metadata is retained. Inspect the actual account's logging, sharing, observability and organization settings. Public defaults do not prove this account's configuration. [OpenRouter data collection](https://openrouter.ai/docs/guides/privacy/data-collection).
- `data_collection:"deny"` excludes providers classified as collecting data; `zdr:true` filters inference endpoints according to OpenRouter's policy classification. ZDR does not cover enabled third-party plugins/tools. OpenRouter's ZDR definition permits some in-memory prompt caching; it is not a promise of no transient processing anywhere. Endpoint-specific policies and account/BYOK declarations can differ from provider defaults. The returned endpoint JSON did not expose account-specific eligibility or contractual evidence. [ZDR boundaries](https://openrouter.ai/docs/guides/features/zdr).
- Google distinguishes training restrictions from retention. Its current Cloud guidance describes possible abuse-monitoring logging, optional request/response logging and model-dependent implicit caching, including durable cache configurations. Direct Cloud defaults do not prove the policy of OpenRouter's shared Vertex endpoint. Obtain the applicable endpoint agreement/classification and account eligibility; do not infer a universal retention duration or no-storage promise from the API flags. [Google data governance and retention conditions](https://docs.cloud.google.com/gemini-enterprise-agent-platform/resources/zero-data-retention).

**Unresolved:** actual account settings, applicable upstream agreement/exemptions, exact admitted endpoints, cache configuration, region, all-in billing bound and availability through retirement. No provider support request, account inspection or authenticated metadata request was made. These are activation blockers, not failures to waive. FERPA-first describes the product direction; these controls do not certify legal compliance. Institution-dependent review remains separate.

## Existing controls and reservation arithmetic

Source inspection at `8768392` found the following implemented constraints; this is not a fresh production-policy attestation:

- `budget-contract.ts` accepts only four general kinds and a small explicit candidate-model allowlist. DB policy supplies model, endpoint, response-provider allowlist, byte/token/price limits, purpose, evidence hashes and a short expiry. Environment model overrides do not replace the route.
- `providerBudgetParameters` supplies one model, one `only`/`order` slug, `allow_fallbacks:false`, `require_parameters:true`, `data_collection:"deny"`, `zdr:true`, `max_tokens` and prompt/completion `max_price`. The base-slug caveat above still applies.
- The gateway allows **one HTTP attempt**, with a 25-second attempt timeout inside the 60-second gateway deadline. It rejects truncation, refusals, empty/invalid JSON and schema failures. It does not automatically retry or choose another model.
- Current source packing is whole-record and permission-scoped: 28,000 total UTF-8 bytes, category caps of 8,000 project / 16,000 interviews / 4,000 learnings / 2,000 contacts, and at most 49 selected records. A further 40,000-character system/user guard applies. These are payload bounds, **not tokenizer proofs**, and exclude any claim that JSON/schema overhead costs zero.

The current evaluator requires a route reservation at least as large as the endpoint's **entire context ceiling**, plus 2,500 bounded billable output tokens. It does not substitute the smaller packed payload for that ceiling. At observed 2.5 rates, the upward-rounded reservation is:

`ceil((1,048,576 × 100,000 + 2,500 × 400,000) / 1,000,000) = 105,858 microdollars = $0.105858`

Eight sequential reservations total **$0.846864**, within the $0.90 evaluator ceiling **only if the endpoint-specific all-in bound is valid**. This is arithmetic, not a measured charge or approval. With the same conservative policy, 3.1 at $0.25/$1.50 would reserve $0.265894 each, so eight calls would require $2.127152 and cannot fit the existing $0.90 plan. Do not silently change v6's model, cap, fixture hashes or route evidence to run that comparison.

The owner's ceiling remains **$25 total**. Preserve the permanent $1 fixed-workshop carve-out and all prior/uncertain usage; general allowance is at most $24 including its reviewed opening hold. Reservations, actual charges and unknown outcomes remain append-only accounting. A capped key is an extra layer, not replacement money or a per-user budget. [Budget operations](ai-budget-operations.md).

The actual runtime evaluation key must be dedicated, non-management, **non-resetting (`limit_reset:null`), at most $0.90**, include BYOK in the limit and have remaining allowance for the entire next reservation. The server checks that same key at the fixed `/api/v1/key` endpoint before claim. Do not inspect a different CLI key, use an unlimited ambient key, or log a key/metadata envelope. The official current-key reference exposes these fields; this review did not read any real key.
